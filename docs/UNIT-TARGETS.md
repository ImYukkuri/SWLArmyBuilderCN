# 单位分类与词条目标

本次整理基于现有 186 张单位卡的类型记录，另外对缺失或疑似特殊类型核对本地原卡图。没有把新规则中的类型猜测套到旧卡上：当前帝国黑暗士兵仍按原卡的 Droid Trooper、Range Troopers 仍按 Trooper 保存。

## 单位字段

| 字段 | 用途 |
| --- | --- |
| `unitCategoryId` | `trooper` 士兵或 `vehicle` 载具，单选 |
| `unitSubtypeId` | 引用 `catalog-definitions.json` 的 `unitSubtypes`；普通士兵为 `null` |
| `nameIdentityId` | 稳定名称标识；按英文基础名建立初始分组，不含称号。修改显示名称不会自动修改标识 |
| `unitTypeId` | 保留的旧版混合类型 ID，编辑分类时同步，继续支持现有升级限制 |

分类字典中的 `categoryId` 表示父类型，`legacyTypeId` 表示旧规则兼容 ID。单位保存时同时检查父子关系和新旧类型的一致性。名称标识由单位 JSON 动态去重生成下拉，不维护第二份名称清单。新建标识可手填，保存后进入选项；名称标识不是唯一单位或 TTS 名称规则的替代品。若某标识仍被其他卡引用，最后一个单位不能直接离开该标识，需先调整引用，避免产生失效规则。

## 关联目标：始终 OR

```json
{
  "id": "detachment",
  "parameter": "Droid Trooper 或 IG-100 MagnaGuard",
  "parameterRefs": [
    { "kind": "unitSubtype", "id": "droid_trooper" },
    { "kind": "nameIdentity", "id": "ig-100-magnaguard" }
  ]
}
```

支持 `unitCategory`、`unitSubtype`、`nameIdentity`、`unit`（本地卡牌 ID），另支持真实卡面所需的 `rank`（军阶 ID）。旧 `parameterRef` 单目标和 `unitType` 混合类型仍可读取。`parameter` 用于文字兼容，存在引用时按 ID 匹配，显示中文名称由当前字典解析。手动编辑参数会清除所有目标引用。

- 附属：任何目标满足即为母单位；同一个母单位同时匹配多个条件只计一次，自己的同款单位不作为母单位。各候选单位上限按匹配母单位数量计算。
- 显式附属目标取代重复的 `quantityLimitedBy`；当前数据已迁移并删除重复字段，保存旧记录时也清理重复限制。没有关联的历史记录仍按旧限制读取，无法解析的附属显示 `unknown`。
- 统率：每个词条提供一个名额，多个目标是同一名额的备选。分配使用增广匹配，避免宽泛条件抢走狭窄条件的唯一目标；同一个单位实例最多豁免一次。
- 军阶引用在写表器中按当前军队／战斗部队的有效军阶匹配。帝国探测机器人原 `Va` 参数由卡面特种部队符号校正为军阶 3。
- 侍从等战斗时点词条可记录相同目标结构并显示，但不会新增组军限制。佣兵、AID、Independent 继续使用可手填参数。

## 字典加载与验证

编辑器复用一次并发 JSON 预载；分类、名称和目标选项在内存生成，输入和下拉不重新拉取整库。单位保存后重建内存选项，重新进入页面时读取最新 JSON。

JavaScript / Python 测试覆盖 OR 去重、同名／精确卡牌区别、统率名额重分配、旧引用兼容、附属添加与孤立校验、军阶条件、类型互斥、无效引用拒绝和隔离目录保存回读。浏览器另外验证桌面与窄屏下拉及候选可用性。
