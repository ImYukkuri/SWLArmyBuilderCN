# 数字 ID 与个人选卡排序

`data/units.json` 和 `data/upgrades.json` 的每张主记录新增正整数 `numericId`，两类卡各自编号；引用时必须同时知道类别。现有 `id`、规则关联、军表保存和分享格式不变。双面升级的两面共用主记录编号。

数字 ID 由本地保存接口分配，编辑器只读显示。新建／复制忽略草稿中复制来的编号，分配新号；普通编辑禁止改号，单位改固定 ID 保留数字 ID。每个目录的 `nextNumericId` 单调递增。删除升级时把编号保留在 `retiredNumericIds`，历史恢复沿用该编号，其他新卡不复用。旧历史缺少数字 ID 时，现存卡沿用当前编号，已删除卡使用保留编号。不要手动重排编号或降低计数器。当前分享编码未更改。

浏览器通过 `card-usage.js` 的单个 `cardUsage` 实例维护个人偏好，启动读取一次 `legion-user-preferences`：

```json
{
  "version": 1,
  "units": {"1": {"count": 12, "lastUsedAt": 1795400000000}},
  "upgrades": {"25": {"count": 4, "lastUsedAt": 1795300000000}},
  "favorites": {"units": ["1"], "upgrades": ["25"]}
}
```

运行期只读 Map / Set。排序不写入偏好，包括切换排序模式；各类选择器在本次会话中记住排序模式。缺少数字 ID 的旧目录使用带 `id:` 前缀的固定 ID；派生的免费独特副本／雇佣车辆用 `variant:` 固定 ID 独立统计；双面卡两面共享记录。

- 成功点击添加单位，单位计一次；自动配备的强制／免费卡不算个人选卡。
- 成功装备升级，按实际装备单位数计数；批量选择一次更新内存并安排一次保存。
- “＋”复制单位，单位与实际复制的各升级分别计数。删除不倒扣。
- 收藏只更改收藏状态；候选试算、失败、图片详情、切面、导入、恢复军表和渲染都不计数。
- 默认“常用优先”按次数、最近使用时间、名称、固定 ID、正反面顺序排序；“最近使用”按时间；“收藏优先”先收藏，再次数和时间。名称与点数排序有确定的名称／ID 后备顺序。
- “常用优先”和“收藏优先”的次数排序加入 1 点初始权重：投身战场、顽强、近距离交锋、精良装备、预备物资、瞄准镜、互联瞄准阵列、机载通信频道、破解通信单元、通信干扰器、载具中队队长、速度爆发、原力引导、战斗心智、原力反射、火控、临时命令、警戒、地下联系，以及 `slotIds` 含 5 且 `rules.requiredDivisions` 含 Light／Dark 的原力卡。权重由 `card-usage.js` 计算，实际次数不含权重，启动不为预设值写入存储，刷新也不会累计预设值。
- 四大阵营（1／2／4／5）及其下辖战斗部队，所有排序模式均先显示本军单位，再显示佣兵，组内使用所选排序。按规则引擎的当前 `armyMembership(...).tierPools` 判断，沿用战斗部队继承和显式覆盖，不根据卡名或其他阵营的佣兵身份判断；曼达洛与暗影集会不应用此分组。
- 修改后防抖 800 ms；`visibilitychange`（隐藏）、`pagehide`、`beforeunload` 尽量刷新。无修改不写入。存储禁用、数据损坏、写入失败不阻止选卡；写失败保留内存脏标记，下次修改／离开时重试。私密模式、强制结束浏览器或存储不足时无法保证持久化。

记录只存在当前浏览器、当前站点，不写回卡牌 JSON，不上传，也不包含在军表或分享链接中。不同标签页各持有启动快照，最后一次成功保存覆盖偏好，不跨标签页实时同步。军表库已有的保存机制独立于此偏好键。
