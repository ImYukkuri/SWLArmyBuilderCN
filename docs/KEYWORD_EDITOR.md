# 词条编辑器

本地数据维护中心和各维护页面的「词条」入口打开 `keywords.html`。支持以 `?id=noncombatant` 直接打开指定词条。

- 可编辑中英文名称、简写、完整规则、多个触发时机与校对状态。
- 名称、ID 和效果正文均可搜索，支持按时机及缺失文本筛选。
- 预览默认显示简写，可切换完整规则；换行和行动标识可直接预览。
- 新词条保存后进入单位、升级卡等页面的词条选项，重新载入相关页面即可读取。已有 ID 不允许在表单中修改，避免破坏引用。
- 保存、新建、重新载入和导出固定在顶部，支持 Ctrl/Cmd+S。
- 未保存修改在切换或离开时提示；保存失败与版本冲突不会清空草稿，也可导出当前草稿。
- 显示单位、升级卡、武器和指挥卡中的直接词条引用。历史恢复只替换当前词条，保留其他记录。

数据仍保存在 `data/catalog-definitions.json` 的 `keywords`，没有新增运行数据源。名称之外的字段沿用现有 `summary`、`full`、`timing` 和可选 `status`；`upstreamIds` 等已有元数据保留。时机为空表示未分类，编辑器不负责改变规则引擎的机器化行为。

本地接口：`GET /api/keywords`、`POST /api/keywords/save`、`GET /api/keywords/history`、`POST /api/keywords/restore`。新增与修改统一使用原维护存储的 revision、原子写入和保存前快照。词条和指挥卡共用整个定义文件的 revision 与锁，因此任意一边保存后，另一边的旧草稿会收到 409，不能覆盖新内容。快照保存在本地 `history/keywords`。

普通静态服务下可浏览、编辑和导出草稿；需要本地 Python 维护服务才能写入源文件。公开站点构建仍只包含写表器，词条编辑器与写入接口留在本地。
