# 战斗部队 V2：规则维护与写表器验证

## 当前范围

伍基人林地战团（21）、224 装甲师（27）、自定义克隆人营（28）与非正规军（29）已启用 `engineVersion: 2`、
`status: "preview"`，可以从所属势力的战斗部队下拉框选择、添加单位及升级，
保存军表并重开。飞机卡牌尚未录入，校验仍提示资料缺项，不表示规则已全部完成。

旧战斗部队及曼达洛规则继续运行旧引擎。新版维护表单已有独立入口；旧部队军阶数据迁移和
曼达洛选择方案迁移尚未实施。旧版维护表单链接到 V2 编辑器，不覆盖 V2 配置。

## 维护入口

本地服务 → 数据维护 → **V2 战斗部队**（`battleforce-editor.html`）。
可用 `#28` 等本地部队 ID 直接定位。当前编辑已经接入的四个 V2 部队，不自动迁移旧部队。

- **基础**：中英文名称、所属势力、开放状态、侦察／标准军阶及组合配额。
- **共通规则 / 规则组**：规则正文、单位与升级许可、独特升级白名单、数量限制、军阶调整、卡牌属性修改、局部词条。
- **选择方案**：选择组、候选规则组、最少／最多数量；增删复制与引用校验。
- **预览**：无需保存即可切换特质、测试单位和军阶、装备升级，对比原卡与当前费用、词条、武器和槽位，显示军表校验问题。

卡牌和枚举下拉来自现有 JSON，**刷新卡牌选项**保留规则草稿。许可和卡牌修改使用本地 ID。
修改支持设为／增加／移除；局部词条的简写、全文、英文、时机及分配条件在弹窗中编辑。
词条修改下拉会合并当前规则包的临时词条，例如“果决”；保存为 `bf:<部队 ID>:<局部词条 ID>`。
运行时只在对应规则组激活且目标条件满足时注入该词条，保留简写、全文和时机，不会泄漏到其他部队或未选规则组。
更换字段、展开表单不丢失已展开的修改器。预览不改卡牌 JSON，也不写入实际军表。

保存沿用 `/api/slot-rules/save`，检查规则包与目录版本，写入历史快照；名称同步到部队目录。
冲突保留未保存内容，离开页面有提示，亦可导出整个规则包草稿。错误配置不能保存。
新页面属于本地维护工具，不包含在公开 Pages 构建中。

224 的标准／侦察配额、单位上限、独特升级白名单与指定升级额外一份已接通。
战壕奇兵直接引用已有本地 ID，在战斗部队内临时设为特种部队；不修改原卡。
四张额外副本使用运行时 `rules.unique=false` 和 `rules.limit += 1`，
整军最多两份，原始唯一性和宿主限制保留；没有新增升级槽规则。
现有卡牌授予槽位继续由原槽位引擎处理。
待补卡牌及验证清单见 [224 接入记录](battleforce-224.md)。

## 数据与执行路径

定义仍保存在 `data/slot-rules.json.battleForces[armyId]`，单位和升级共用原来的 JSON。
缺省版本或 `engineVersion: 1` 使用旧引擎；未知版本拒绝执行，不能回退到旧引擎。
`draft` 只作诊断，`preview` / `active` 执行 V2 效果。

```text
原始单位 / 升级 + 战斗部队定义 + 军表选择及装备
  → BattleForceRuntime.resolve
  → 有效单位、有效升级、每个单位实例的属性、有效军阶配额
  → RulesCore / BuilderModel / 写表器候选、卡片及详情
```

运行时副本不写回卡牌 JSON。缓存以原始数据对象和完整军表内容为键，最多保留
8 份结果；每次修改都从原数据重新计算，防止叠加效果累计到下一次渲染。
切换战斗部队、关闭军表或重开另一份军表会重新选择有效数据来源。

`battleforce-v2.js` 负责配置和选择校验，`battleforce-runtime.js` 负责效果。
Python 的 V2 军表校验及配置保存通过 `battleforce_bridge.py` 调用
`tools/battleforce-node.cjs`，不维护第二套游戏语义。旧 Python 校验仍保留。

## 定义格式

```text
engineVersion: 2
status: draft | preview | active
v2:
  parentFactionId: 本地势力 ID
  common: 效果范围
  ruleGroups: [{ id, name: { en, zh }, ...效果范围 }]
  selectionSchemes: [{ id, name: { en, zh }, groups: [
    { id, name: { en, zh }, ruleGroupIds: string[], min, max }
  ] }]
```

每个效果范围可包含：

| 字段 | 用途 |
|---|---|
| `textRules` / `textRulesZh` | 战斗部队说明文字，不直接执行局内操作 |
| `unitGrants: [{unitId}]` | 基础及所选规则组的单位许可取并集 |
| `upgradeGrants: [{upgradeId}]` | 覆盖势力可用性；宿主、槽位、互斥、唯一性仍检查 |
| `uniqueUpgradeIds: string[]` | 有此字段时，限制可选的独特升级；各范围取并集 |
| `unitLimits: [{unitId,min,max}]` | 单位数量约束，与军阶配额分别计算 |
| `rankModifiers: [{rankId,op,min?,max?}]` | 军阶配额修改 |
| `modifiers` | 临时卡牌属性修改 |
| `entries` | 带名称、简写、完整规则及时机的局部词条，复用标签与弹窗 |

卡牌授权和指定卡牌修改使用本地卡牌 ID，不使用英文名称或外部编号。
匹配条件复用 `RulesCore.evaluate` 的 `all` / `any` / `not`，支持本地单位 ID、
名称标识、类型、子类型、势力、组织、军阶和词条。局部词条的 ID 带战斗部队前缀，
不加入全局词条 JSON。

修改器结构为 `{id,card,target?,upgradeId?,field,op,value,count?,when?,weaponFilter?}`。
目前实现费用、势力、组织、军阶、数量上限、独特性、互斥、单位词条、武器词条和槽位。
数值 `set` 在 `add` 之前执行，数值增加可叠加；同词条及同参数的数值可叠加，
无数值词条去重。相同目标键上的不同 `set` 报错并保留原值，不以配置顺序选胜者。
身份属性先计算，再处理依赖有效军阶等属性的效果。装备条件目前只支持
`when: {equippedSlot: "personnel"}` 这一类“已装某槽位类别”的条件。

武器筛选支持近战 / 远程、原武器是否含指定词条。宿主的武器修正同时应用到
单位武器和升级提供的武器，包括正面、反面与双面显示；每次只应用一次。

## 军表存档与槽位

```json
{
  "battleForceSelection": {
    "battleForceId": 28,
    "schemeId": "clone-traits",
    "groups": {
      "ccb_battalion": ["ccb_assault"],
      "ccb_jedi": ["ccb_decisive"],
      "ccb_veteran": ["ccb_reinforced"]
    }
  }
}
```

三组分别有 3 / 3 / 6 个候选，各选一项。未选满时允许继续编辑，但校验提示缺项。
超量、重复或失效引用不激活对应规则。取消授权不会静默删除已加入的单位，
单位保留并显示不符合当前部队；取消额外槽位则移除其中的升级及其继续授予的槽位装备。
槽位依靠类别、授予来源、效果 ID 和出现序号匹配，避免把失效槽中的升级挪到其他空槽。

BARC 使用 `republic-barc`，在此营中仅按支援军阶加入。旧存档中的指挥官 BARC
保留但报告军阶不合法，需移除后从支援重新加入。
每个实例保存加入时的 `rankId`；引擎仍支持按配置授予额外军阶。
切换部队会清空全部单位及其升级，并清除 V2 规则组选择；再次选择当前部队不清空。
非正规军使用 `empire-laat-empire`。

本地存档、复制和原生 JSON 保留完整状态。TTS JSON 没有特质及实例军阶字段：
导出明确提示缺失，导入可匹配普通装备，但需要重新选择特质并核对单位军阶。
依赖未恢复特质才能提供的槽位不能猜测分配，仍返回可处理的导入错误。

## 手工验收步骤

1. 银河共和国 → 自定义克隆人营，选择突击、果决、增援。
2. 指挥官入口不出现 BARC；从支援入口加入并检查军阶计数。
3. 加入绝地武士将军，装备光剑；候选及武器栏应出现致命 1，点击果决可读规则。
4. 给核心士兵的额外人员槽装备升级；改选装甲支援后，额外槽及其中装备消失。
   装甲支援下，普通人员槽有装备时获得机械化步兵，卸下后移除该词条。
5. 切换睿智，检查援助：克隆人士兵；保存并刷新，三组选择及实例军阶保留。
6. 切到 212 攻击营，单位及升级全部清空，费用与激活数归零，旧规则候选正常。
7. 义军 → 非正规军；检查帝国 LAAT/le、TX-225、WLO-5 的义军属性及各至多一辆；
   两个义军特工可以各装隐秘破坏者，其他宿主限制仍然有效。

## 自动验证及后续阶段

- `npm test`：既有规则回归、V2 配置 / 存档 / 效果 / Python 桥接测试。
- `npm run test:scroll`：桌面与手机的实际点击、选择、保存重开、切换部队、槽位移除和弹窗。

- `npm run build`：静态写表器包含 V2 浏览器模块；本地维护与 Node 桥接不打包。
