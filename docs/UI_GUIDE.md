# 军表编辑器 UI 规范

本规范用于 index.html 军表编辑器。维护页面继续使用独立的 style.css。

## 视觉与布局

编制档案采用浅灰蓝背景、白色内容区、深蓝文字和低饱和阵营标识。桌面保留左侧军表、右侧候选资料库，右侧随页面滚动保持可见。760px 及以下由槽位触发选择抽屉，共用候选组件。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| --bg | #eef1f4 | 页面背景 |
| --paper | #ffffff | 内容底色 |
| --ink | #253540 | 主文字 |
| --muted | #63737e | 辅助文字 |
| --accent | #285d79 | 选择、导航与主要操作 |
| --line | #d8e0e6 | 分隔 |
| --faction | #8b4b53 | 单位身份标识 |

正文使用系统中文无衬线字体；英文与数字使用 Bahnschrift / Aptos / Segoe UI。单位名称 15–17px，规则正文 12–13px，辅助信息 10–12px。紧凑元素间距 4–8px，项目内边距 10–18px，桌面两栏间距 18–24px。图标复用本地 LegionSymbols 字体及简单界面 SVG，不依赖网络字体。

## 势力入口与军表保存

最外层为六个势力和已保存军表：义军、银河帝国、银河共和国、分离主义势力、曼达洛人、暗影集会。新建军表默认 1000 分，战斗部队为“无 · 基础规则”。战斗部队列表仅包含现有数据声明属于该势力的部队；曼达洛人与暗影集会的基础选择仍保留其自身军队规则。

编辑器顶部可改军表名称、战斗部队和分数。600 分及以下使用 recon，超过 600 分使用 standard；配置再叠加 battleForces[armyId].modes 对应档位。军阶按钮显示实际数量和配额，组合上限显示在下方。切换战斗部队保留已选单位与升级，重新进行规则校验。

军表自动保存，并提供“保存军表”按钮。首页可打开、搜索、复制、删除和撤销删除。浏览器集合键为 swl-army-library；旧 swl-army-draft 仅迁移一次，保留原始备份及实例 ID。新建军表和复制军表不会覆盖其他记录。保存失败会保留编辑器内的修改并明确提示。保存范围是当前浏览器和站点地址。

builder-library.js 提供势力映射、规则档位和集合持久化；builder-home.js 负责入口、导航与保存交互。server.py 显式放行所有编辑器模块。tests/test_builder_server.py 会通过真实 HTTP 请求检查 index.html 引用的全部脚本和样式，以覆盖本地 8770 启动路径。

## 单位的四种呈现

1. 军表简略：默认状态。第一层并排放名称、弹性属性栏和费用，英文名固定在中文名下一行，第二层放军阶、类型和双语称号，第三层放槽位或升级及其费用、删除操作。窄屏将属性栏换到下一行；属性栏空间足够时显示中文释义。
2. 军表展开：继续显示时点分组词条、近战可用武器/远程武器、升级效果。词条释义可单独展开，也可全局打开。
3. 单位详情：点击紧凑摘要打开完整信息，词条简写默认展开。图像和交互按钮分别处理自己的操作。
4. 候选单位：采用裁剪卡图在左、其余资料在右的独立排版；复用属性、槽位、词条和武器模块。词条前用色条和阶段名称表示时机，多时机逐项展示。点击候选正文或键盘回车/空格直接选择，词条、图像和展开按钮不会误选；展开后显示词条简写。

单位缩略图使用 assets.portrait；点击后加载 assets.front。升级卡仅使用现有图片字段；战术/指挥卡主区和选择器均展示完整原卡图，命令对象与完整卡文以紧凑遮罩覆盖下半部，左上另有卡名和牌点小遮罩。点击遮罩可选择或替换，点击未遮挡的卡图查看大图；收起卡文后只留展开按钮。主区固定两列，六张非待机指挥卡排列为三行，待机命令缩为标题旁标记。选择器按容器宽度自适应列数，卡片高度随正文自然伸展，不截断规则。

## 分组与装备

- builder-model.js 按单位版本和完整升级配置生成显示组，忽略实例 ID 和升级数组顺序。存储仍保留独立单位。
- 普通单位使用加减按钮。复制整套升级并重新生成全部实例 ID；单位或升级具有独特性时显示删除按钮。
- 同组默认仅修改一个单位；升级面板可勾选“应用到全部单位”。复制、移除导致分组变化时重新确认批量范围。
- 批量替换先在临时军表中移除所有被替换项，再逐个检查条件及整军冲突；全部通过才替换当前军表。
- 未完成军表的必选槽位、军阶最低数量和点数问题继续显示在校验中，不阻止编辑；新增或复制不得进一步超过军阶及组合上限。新的非法装备、同名冲突、独特性和数量上限会阻止本次操作。
- 单位筛选与实际加入共用 addUnit 事务。默认隐藏所有已占用独特身份和不合条件的候选；“显示不可选”可查看状态与原因。升级整卡点击选择，没有额外装备按钮。
- 独特角色同时检查单位与升级。组合单位通过 requiredChildren 预留必带独特角色；名称逗号前缀只有匹配现存独特单位名时才作为角色身份，不使用手写昵称映射。必带升级与自身宿主不冲突；导入或旧存档中的重复身份仍由 rules-core.js 报错。
- 失效单位和失效/孤立升级保留可见删除入口。点数仍使用规则引擎的 basePoints；规则判定与有效费用继续由 rules-core.js 负责。

## 规则和武器

词条按规则引用、数值、参数与行动类型去重，保留升级来源。浮窗显示现有简写、完整规则及来源升级详情。未提供的说明不会自行补写。

武器共用深色紧凑条，双语名称和来源并排；近战红、远程蓝、兼用射程渐变。射程下限为 0 的武器列入近战可用组。负攻击骰数显示 X，并保留来源升级的实际效果说明。

升级效果与使用要求优先展示，关联词条在同一流式区域内排列，关联武器由按钮打开属性。横置/一次性标识仅从现有卡文明确的自身使用标记识别；没有依据时隐藏，不从外部参考库补齐。

## 文件职责与验证

- builder.js：数据载入、现有规则适配、选择与保存。
- builder-model.js：显示分组、复制、原子装备事务。
- builder-view.js：共享展示组件、抽屉、对话框及词条浮窗。
- builder.css：仅军表编辑器的视觉体系。
- tests/builder-model.test.cjs：分组、实例隔离、装备事务、独特性、数量限制和互斥替换。

运行 npm test 执行 Python 回归及 Node 模型测试；npm run build 创建本地静态产物。视觉验收需实际运行页面，检查桌面两栏、手机三个选择抽屉、长名称、多武器、选中/不可选、嵌套弹窗以及刷新保存。截图保存在仓库外。
