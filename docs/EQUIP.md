# Equip：指定卡牌与槽位

单位编辑器的「Equip · 必带卡牌与槽位」使用同一处入口，分别选择「升级卡 / 伙伴卡」或「槽位」。选项来自已预载的本地卡牌和槽位字典。

```json
{
  "equipUpgradeIds": ["caught-in-a-web"],
  "equipSlotIds": ["doctrine", "armament"]
}
```

- `equipUpgradeIds`：现有的本地升级卡 ID。加入单位时遍历实际槽位，执行真实选卡操作，处理后续解锁的槽位。伙伴卡仍使用升级卡 ID。
- `equipSlotIds`：`slot-rules.json` 的语义槽位 ID，例如 `doctrine`（学说）、`armament`（武装）。每个类别至少装一张该类别升级；多个类别分别满足。不会替玩家选择升级卡。
- 同类槽位有多个时，任意一个合法匹配的已选槽即可满足该类别。未选时标记一个实际槽为必选。基础槽位自己的 `required` 和灵活响应等严格限制继续独立执行。
- Equip 不新增槽位。当前军队规则移除关联槽位后，军表报告缺少可用槽；删除已装升级后，必选提示恢复。允许保存未完成的编制，不阻止逐槽装备。
- 前后端 `slotListFor` / `slot_list_for` 共用对应语义，候选单位、军表主界面和最终校验都读取实际槽位记录。

## 兼容旧数据

字段不存在时，读取旧 `equip` 词条的 `parameter`（如 `Equip: Doctrine, Armament`、`学说、武装`）、`kind: slot` 引用和旧基础槽位的必选标记。文本仅按槽位 ID 或字典名称精确匹配，不猜测卡名或 OCR 符号。

`equipSlotIds: []` 明确表示没有槽位型 Equip，不再回退到旧词条文字。当前 10 张槽位型 Equip 单位已迁移；帝国军官的学说目标另核对了原卡图。编辑旧数据时，首次修改槽位关联会搬移对应旧必选标记，防止移除关联后仍残留限制。其他独立必选槽不会随着新的显式 Equip 关联被删除。

Equip 在写表器中显示为“配备：中文目标名”，分类读取词条的 `timing`，不在前端写死。经用户确认，Equip 属于 `army_building`（组军）；主界面隐藏组军词条分组，单位详情和候选选择继续显示。显示参数从关联 ID 动态读取，具体卡牌／伙伴显示中文卡名，槽位显示中文槽位名；多个必带目标用顿号连接。即使单位没有单独的 equip 词条记录，只要配置了 Equip 关联，也会生成展示用词条。单位候选、展开详情与词条弹窗使用相同名称，并保留简写／完整规则切换。具体卡牌自动装备逻辑、必选槽位提示和卡牌费用不变。

目标卡缺少中文名时保留英文原名，不根据相似名称猜测对应卡。

升级卡新增的槽位在显示时紧跟其来源升级卡，自动选卡跳转也使用相同顺序。多层新增槽位按来源嵌套排序；槽位变化时按类别、来源卡和同类序号重新关联已选升级，避免新增或删除槽位后卡牌错位。

## 没有槽位也能装备的特殊升级

`rules.slotGrants` 中的 `trigger: unitQualifies` 仍使用现有持有者名单／条件。满足条件的单位若已有对应普通槽位（包括其他卡或战斗部队增加的槽位），卡牌按原有条件在该槽位中选择；普通槽位被占用不会额外生成专用槽。

没有对应普通槽位时，每张符合条件的卡分别生成 `special:<升级卡ID>` 槽位，名称为 `【升级卡中文名】`，无中文名则使用英文名。每个专用槽只接受其关联卡牌，不再共用 `gear_exempt`、`training_exempt` 或 `crew_exempt`。例如 B1 的电子望远镜和便携式扫描仪各有一个槽，可以同时装备。该规则不豁免卡面限制、独特／数量限制及其他选卡校验。

新军表记录 `slotLayoutVersion: 1`。打开旧存档或导入原生 JSON 时，按原共享槽布局读取已选卡，再迁移到对应独立槽，保留卡牌 ID、实例 ID 和正反面状态。TTS JSON 继续使用卡名，并在导入时计算当前槽位。新增普通槽会优先容纳已装的特殊卡；容量不足时拒绝此次选卡操作，提示先处理相关升级。删除授权卡或切换战斗部队后无法匹配的卡仍保留为可删除的失效升级，不会悄悄丢弃。
