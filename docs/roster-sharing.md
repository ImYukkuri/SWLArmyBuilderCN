# 军表路由与分享

普通编辑地址为 `#faction/<势力 ID>/army/<本地军表 ID>`，只索引当前浏览器的军表。刷新从 `BuilderLibrary` 恢复，不在编辑或切槽时序列化军表到 URL。`#faction/<势力 ID>` 新建该势力军表，旧 `#army/<ID>` 地址仍可打开本地记录。

点击“生成分享链接”时，快照当前原生军表记录，使用浏览器原生 DEFLATE（zlib 包装）压缩 UTF-8 JSON，再编码为无填充 Base64url。版本 1 格式为 `#share/1.<代码>`。只需现有首页，不需要额外的分发页、API、压缩库或服务端存储。分享时保留当前页面的域名和部署路径，移除查询参数及旧路由；不硬编码 GitHub Pages 地址。

首页加载现有目录后，优先识别分享代码，通过 `BuilderTransfer.readNative` 走原生导入迁移，以新记录 ID 保存，随后打开对应势力和战斗部队的写表器，将地址替换为短本地路由。刷新不会重复导入，也不会按发送者的记录 ID 覆盖接收者的军表。规则组选项、单位实例军阶、装备槽位、正反面／双面、指挥卡、备用卡、三类任务卡和其他原生字段均由 JSON 保留；仅新建本地记录身份及时间戳，旧格式字段执行既有迁移。编制校验问题保留给写表器显示，不自动删除卡牌。

分享内容放在 URL 片段中，不随首页请求发送给静态服务器。普通本地地址不能跨设备还原军表；跨设备应使用分享按钮生成的链接。每次链接是静态快照，修改军表后须重新分享。不支持浏览器压缩 API 时明确提示使用 JSON 文件，不退回超长明文链接。复制失败时提供只读文本框供手动复制。

兼容旧 `?roster=z:<deflate-raw 的 Base64>` 和 `?roster=j:<URL 编码 JSON>` 链接，保留旧 Base64 的 `+`，不会误当空格。也支持 `?share=1.<代码>` 入口。新分享只生成版本 1。损坏、未知版本、超过 256 KiB 的代码或解压超过 1 MiB 的内容会报错，不写入半成品；失败时保留原链接便于重试。解压期间若用户切换页面，丢弃过期的导入结果。

测试：`node --test tests/builder-share.test.cjs`；浏览器分享回归在 `tests/builder-scroll.test.cjs`。原生导入仍以接收端现有目录及迁移规则为准，不把卡牌资料库塞进分享代码。
